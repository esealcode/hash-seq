# What is a Tenet?

The idea of a Tenet came to mind after the NFTs disaster. A lot of NFTs were stolen works and sold on the blockchain without the original artist's permission.
At this time, a question came to my mind: What if a piece of text could be bound to an artwork? Not by storing it inside, not by referencing it externally, but by shaping the artwork itself such that no contestation about the intent would be possible?

That's what a tenet is, it embeds its origin directly into its structure. The link between the text and the artwork is not declared, it is *demonstrated*. It would not solve the issue of anyone stealing your work by any mean, but it would give you an immutable proof that it was not meant to be, potentially helping with legal actions.

Later on, I realized that this could be generalized to any object that would end up as somewhat an "observable entity".

In essence, a *tenet* is an entity that is intrinsically tied to a text through a set of observable attributes. These attributes are not chosen arbitrarily; they are derived from the text itself in a way that is deterministic, verifiable, and, in practice, impossible to intentionally replicate with any other text.

In this article, we introduce the foundation of that system: how a text is transformed into a set of attributes, how those attributes are expressed in an entity, and why this connection holds with strong guarantees in practice.

# The System

At its core, the system links a **plaintext** (a contract, statement, or intent) to an **entity** (like an artwork) through a layer of **attributes**.

There are three elements:

- A **plaintext** \(T\): whatever text you want to bind (e.g. ownership rules, conditions)
- A **kernel** \(K\): a deterministic function.
- A set of **attributes** \(x\): the observable features embedded in the entity

The process is as follow:

\[
T \xrightarrow{K} x
\]

The plaintext is passed through the kernel, which outputs a specific combination of attributes. The entity is then created so that it visibly contains exactly those attributes.

## The plaintext

The plaintext is the piece of text that rules over the entity. Self-reference is at the core of a plaintext and by self-referencing, an entity explicitly claim authority upon itself. However, not everything can be stated within the plaintext and it is important to define the extent and boundaries of such authority, we describe them with the following rules:

- A tenet shall possess the authority to act solely upon itself or upon any entity that has expressly granted its consent for the tenet to exercise such authority, provided that the entity possesses the requisite authority to grant such consent.

Note that additional rules may be applicable, subject to the judgment of all parties involved in assessing the entity's plaintext validity.

## The Kernel

The kernel is the key of the system.

It is defined as a deterministic function:

\[
K : \mathcal{M} \to \mathcal{X}
\]

where \(\mathcal{M}\) is the set of all possible texts and \(\mathcal{X}\) is the set of all possible attribute combinations.

A valid kernel must be deterministic and output an uniform distribution of attributes combinations.

Formally, for any plaintext \(T \in \mathcal{M}\) and any attribute combination \(x \in \mathcal{X}\):
\[
\Pr[K(T) = x] = \frac{1}{|\mathcal{X}|}
\]

To support the robustness of the system, we require the attribute space to be large enough to make in impossible to intentionally replicate the same attributes with any other text.

In practice, we require that there are at least \(2^{128}\) possible attribute combinations such that:
\[
|\mathcal{X}| \ge 2^{128}
\]

If the above is respected, it ensures that:

\[
\Pr[\text{another text } T' \text{ such that } K(T') = x] \approx \frac{1}{2^{128}}
\]

An entity (e.g. an artwork) is considered bound to a plaintext \(T\) if it exhibits the attributes \(x\) that are generated by the kernel \(K(T)\). In other words, the entity looks the way it does *because* of the plaintext and the kernel.

You can think of the attributes as a cryptographic/steganographic fingerprint of the plaintext.

In order to bind another plaintext \(T'\) to an entity, an attacker would need to find a different plaintext \(T'\) such that \(K(T') = x\) or another valid kernel \(K'\) such that \(K'(T') = x\) which is not possible in practice.

# What would it look like in practice?

A common approach would be to take the plaintext as a UTF-8 string and send it through the kernel that will run it through a sha256 hash function. That would give the kernel enough entropy to kickstart an internal counter based PRNG by repeatedly hashing the plaintext with a counter to get the next entropy bits. Then, a trivial kernel could for instance generate random hex color codes from it, outputting 6 hex color codes would be enough to reach the required kernel output space size. 

You would then build the entity by creating an image that would render those colors in order which would then realize the binding with the plaintext.

# Conclusion

The system described here is built on a simple but powerful idea: a piece of text can deterministically generate a set of attributes so large and unpredictable that any entity expressing them becomes, in practice, uniquely tied to that text.

A tenet is the result of this process. It is not just an object associated with a statement—it is an object whose very structure reflects that statement. The link does not rely on storage, signatures, or external authority. It emerges from the improbability of reproducing the same attributes from a different source.

Under the right conditions, a fixed and unbiased kernel, a sufficiently large attribute space, and unambiguous interpretation, the binding holds with strong guarantees. Producing the same attributes from another plaintext becomes equivalent to solving a problem with at least 128 bits of complexity, placing it far beyond practical reach.

This shifts the way we can think about ownership, authorship, and meaning. Instead of attaching metadata to objects, we can embed constraints directly into their form. Instead of trusting declarations, we can rely on their structure.
